# Build 48A: staged HTTPS reviewer gateway

The existing authenticated API, live verifier and proof server remain loopback only. A new gateway on 127.0.0.1:4195 serves the production builds, forwards a narrow allowlist of the current onboarding API, checks the exact configured HTTPS origin for POST, preserves the original CSRF check, and appends Secure to the session cookie. Public buyer verification remains anonymous. The full operator UI at /app and its API are protected with a separate high-entropy reviewer password (HTTP Basic over TLS) in addition to normal LOT role authentication. Registration is reviewer-gated, issuance remains explicitly allowlisted and persistently limited to three attempts (including the cloud test already reserved). Do not add a publicly registerable username to the issuance allowlist until the intended account has been created. Do not open raw ports 4175, 4176, 4195, 5173 or 6300.

Stage systemd units with `bash scripts/lot-stage-cloud-services.sh` only after the Azure public IP DNS label is configured and production builds complete. It stores wallet/token secrets in root-readable files on the VM (not in Git, not in browser); the operator and worker must still access the mnemonic in process memory. It refuses replacing existing env files and does not start or stop services. This is a managed dedicated test wallet, not production key custody. The gateway assumes a trusted loopback reverse proxy that overwrites forwarded scheme. A real TLS proxy and public tests remain required. Global request limits are intentionally modest; not a complete DDoS protection solution. No independent security audit. The public gallery is still the four original fixed examples; newly confirmed receipts are accessible by exact link. Do not claim public hosted issuance until tested over HTTPS. No changes to contracts or existing journals.
